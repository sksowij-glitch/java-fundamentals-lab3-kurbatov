## Пояснення та прев'ю коду

Весь код лабораторної роботи розміщено в окремому пакеті у файлі [`Main.java`](Main.java). Код написаний у простому стилі, зрозумілому для початківця, без використання сторонніх бібліотек або складних конструкцій.

### Генерація випадкових даних
* **Пояснення:** Метод `generateRandomArray(int size, int bound)` приймає бажаний розмір масиву та верхню межу значень. За допомогою класу `java.util.Random` масив заповнюється невід'ємними числами типу `long`. Для тестування двох різних методів на однакових даних використовується допоміжний метод `copyArray()`.
* **Прев'ю коду:**
```java
public static long[] generateRandomArray(int size, int bound) {
    if (size < 0) {
        throw new IllegalArgumentException("Розмір масиву не може бути від'ємним!");
    }
    Random random = new Random();
    long[] array = new long[size];
    for (int i = 0; i < size; i++) {
        array[i] = random.nextInt(bound);
    }
    return array;
}
```

### Метод 1: Сортування вибором (Selection sort)
* **Пояснення:** Алгоритм ділить масив на відсортовану та невідсортовану частини. На кожній ітерації $i$ знаходиться індекс максимального елемента (`maxIndex`) серед решти елементів від $i + 1$ до $n - 1$. Якщо найбільший знайдений елемент не знаходиться на поточній позиції $i$, виконується обмін значеннями через проміжну змінну `temp`. У результаті масив упорядковується за спаданням.
* **Прев'ю коду:**
```java
public static void selectionSort(long[] array) {
    if (array == null) return;
    int n = array.length;

    for (int i = 0; i < n - 1; i++) {
        int maxIndex = i;
        for (int j = i + 1; j < n; j++) {
            if (array[j] > array[maxIndex]) {
                maxIndex = j;
            }
        }
        if (maxIndex != i) {
            long temp = array[i];
            array[i] = array[maxIndex];
            array[maxIndex] = temp;
        }
    }
}
```

---

### Метод 2: Сортування вставкою (Insertion sort)
* **Пояснення:** Алгоритм перебирає елементи починаючи з другого (індекс 1). Поточний елемент запам'ятовується в змінну `key`. У внутрішньому циклі `while` всі попередні елементи, які менші за `key` (`array[j] < key`), зсуваються на одну позицію вправо. На звільнене місце записується значення `key`.
* **Прев'ю коду:**
```java
public static void insertionSort(long[] array) {
    if (array == null) return;
    int n = array.length;

    for (int i = 1; i < n; i++) {
        long key = array[i];
        int j = i - 1;

        while (j >= 0 && array[j] < key) {
            array[j + 1] = array[j];
            j = j - 1;
        }
        array[j + 1] = key;
    }
}
```

### 1. Порівняйте та назвіть переваги та недоліки таких методів сортування: сортування бульбашкою, сортування вибором, сортування вставкою.

| Метод сортування | Переваги | Недоліки |
| :--- | :--- | :--- |
| **Сортування бульбашкою (Bubble sort)** | • Максимальна простота розуміння та реалізації.<br>• Легко модифікується прапорцем (`swapped`) для зупинки на вже відсортованому масиві.<br>• Стабільний алгоритм. | • Найповільніший на практиці серед простих методів.<br>• Велика кількість зайвих операцій запису в пам'ять (обмінів). |
| **Сортування вибором (Selection sort)** | • Робить мінімально можливу кількість операцій обміну: рівно $O(n)$ обмінів у найгіршому випадку.<br>• Ефективний, коли операція копіювання/обміну елементів дуже «важка» (дорога). | • Кількість порівнянь завжди рівна $\frac{n(n-1)}{2} = O(n^2)$ навіть на вже відсортованому масиві.<br>• У базовій реалізації є нестабільним. |
| **Сортування вставкою (Insertion sort)** | • Найшвидший серед простих алгоритмів на практиці.<br>• На майже відсортованих масивах працює за лінійний час $O(n)$.<br>• Стабільний, ефективний для масивів невеликого розміру (часто використовується як фінальний етап у гібридних сортуваннях типу Timsort). | • На масивах, впорядкованих у зворотному порядку, виконує максимальну кількість зсувів ($O(n^2)$). |

### 2. Оцініть кожен з методів відповідно до критеріїв: час роботи, потреба у додатковій пам’яті, стабільність. За якими ще критеріями ви можете порівняти ці алгоритми?

| Алгоритм | Найкращий час | Середній час | Найгірший час | Додаткова пам'ять | Стабільність |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **Bubble sort** | $O(n)$ (з прапорцем) | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Стабільний |
| **Selection sort** | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Нестабільний |
| **Insertion sort** | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Стабільний |

**Додаткові критерії порівняння:**
1. **Кількість операцій запису (обмінів):** Selection sort виконує щонайбільше $n - 1$ обмінів, тоді як Bubble та Insertion sort можуть виконувати до $O(n^2)$ операцій запису.
2. **Адаптивність (Adaptive):** здатність алгоритму працювати швидше, якщо вхідні дані вже частково відсортовані (Insertion sort є повністю адаптивним, Selection sort — неадаптивним).
3. **Онлайн-сортування (Online):** здатність сортувати дані по мірі їх надходження без необхідності мати весь масив одразу (Insertion sort може приймати елементи по одному й одразу вставляти їх на потрібні місця).
4. **Складність реалізації:** простота коду для налагодження та підтримки.

### 3. Який випадок є найкращим або найгіршим для роботи цих алгоритмів? Який з методів забезпечить у цих випадках найкращий/найгірший результат?

1. **Частково або повністю відсортований масив:**
   * **Найкращий результат:** забезпечить **Insertion sort (сортування вставкою)**. Він проходить по масиву за один цикл і перевіряє умову, не виконуючи зсувів. Складність складає $O(n)$.
   * **Найгірший результат:** покаже **Selection sort**, оскільки він однаково виконує повний перебір усіх пар $O(n^2)$ порівнянь, незалежно від початкового порядку елементів.

2. **Масив, відсортований у зворотному порядку:**
   * **Найкращий результат:** **Selection sort** (хоча порівнянь буде $O(n^2)$, кількість обмінів залишиться мінімальною — лише $n/2$).
   * **Найгірший результат:** **Bubble sort** та **Insertion sort**. Кожен елемент доведеться переміщати через увесь масив, що потребує максимальної кількості ітерацій та операцій зсуву/обміну ($\approx \frac{n^2}{2}$).

### 4. Що означають позначення O(1), O(n), O(n²)?

Позначення «O-велике» (Big-O notation) використовується в інформатиці для опису асимптотичної верхньої межі складності алгоритму за часом (кількістю кроків) або за пам'яттю відносно розміру вхідних даних $n$:

1. **$O(1)$ — константна складність:**
   * Час виконання (або об'єм пам'яті) не залежить від розміру вхідних даних $n$.
   * *Приклад:* звернення до елемента масиву за його індексом (`array[i]`), обмін двох змінних місцями за допомогою `temp`.

2. **$O(n)$ — лінійна складність:**
   * Час виконання зростає прямо пропорційно до кількості елементів $n$. Якщо масив збільшити у 5 разів, алгоритм працюватиме приблизно в 5 разів довше.
   * *Приклад:* один прохід циклом по масиву для пошуку суми елементів або перевірки наявності числа.

3. **$O(n^2)$ — квадратична складність:**
   * Час виконання зростає пропорційно квадрату кількості елементів. Якщо обсяг даних зросте у 2 рази, час роботи збільшиться приблизно в 4 рази ($2^2$), а якщо у 10 разів — час збільшиться у 100 разів.
   * *Приклад:* класичні алгоритми сортування з двома вкладеними циклами (Selection sort, Bubble sort у гіршому випадку, обхід квадратної матриці).
