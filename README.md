## Відповіді на контрольні питання

### 1. Що таке структурне програмування?
Структурне програмування — це методологія створення програм, за якої код будується у вигляді логічної та зрозумілої ієрархічної структури блоків без використання безладних переходів (наприклад, `goto`).  
Програма будується лише з трьох базових елементів: послідовності команд, розгалужень та циклів, а великі завдання розбиваються на менші підпрограми (функції або методи).

### 2. Назвіть основні конструкції структурного програмування.
Згідно з теоремою Бема — Якопіні, існують три базові керуючі конструкції:
1. **Послідовність (лінійне виконання)** — команди виконуються послідовно одна за одною.
2. **Розгалуження (вибір)** — вибір однієї з дій залежно від умови (`if`, `if-else`, `switch`).
3. **Повторення (цикл)** — багаторазове виконання дій, доки виконується або поки не виконається умова (`while`, `do-while`, `for`).

### 3. Назвіть основні принципи структурного програмування.
1. **Єдина точка входу та виходу:** будь-який блок, функція або цикл повинні мати лише одну точку входу та одну точку виходу.
2. **Модульність (декомпозиція):** складна програма розбивається на простіші, незалежні блоки (методи, класи, пакети).
3. **Низхідне проектування (зверху-вниз):** спочатку створюється загальна структура програми, а потім деталізуються її окремі компоненти.
4. **Відмова від `goto`:** переходи між рядками коду здійснюються виключно через стандартні цикли та розгалуження.

### 4. Поясніть, чому в більшості мов програмування не радять використовувати оператор GOTO, а в мові Java його взагалі немає?
Оператор `goto` дозволяє здійснювати перехід у довільне місце коду, що робить логіку програми заплутаною, важкою для читання, розуміння та налагодження (утворюється «спагеті-код»).  
У мові Java ключове слово `goto` є зарезервованим, але його не реалізовано розробниками мови навмисно, щоб уникнути написання поганого коду. Усі задачі в Java вирішуються циклами, викликами методів, блоками `try-catch` та мітками для `break`/`continue`.

### 5. Що таке спагеті-код?
Спагеті-код (spaghetti code) — це назва заплутаного, погано структурованого програмного коду, у якому важко простежити послідовність виконання, оскільки логіка переходів переплутана, як спагеті на тарілці. Такий код складно розуміти, виправляти та тестувати.

### 6. Що таке проектування зверху-вниз? В чому його переваги?
Проектування зверху-вниз (top-down design) — це підхід, коли розробка починається з формулювання загальної високорівневої мети програми, а потім ця система послідовно розбивається на все дрібніші й детальніші підзадачі (функції, методи), поки кожна дія не стане елементарною.  
**Переваги:**
- Допомагає сконцентруватися на головній логіці програми, не відволікаючись завчасно на другорядні деталі.
- Полегшує розподіл завдань у командній роботі.
- Спрощує тестування за допомогою тимчасових заглушок (stubs).

### 7. Що таке область видимості ідентифікатора?
Область видимості (scope) — це частина програми, у межах якої оголошений ідентифікатор (ім'я змінної, константи чи методу) є доступним для звернення. За межами своєї області видимості змінна не існує, і звернення до неї викличе помилку компіляції.

### 8. Що таке блок? Як блоки впливають на область видимості?
**Блок коду** — це сукупність операторів, обмежена фігурними дужками `{ ... }`.  
**Вплив на область видимості:** змінні, оголошені всередині блоку, мають блочну область видимості. Вони створюються під час входу в блок і знищуються після виходу з нього. Ззовні блоку звернутися до цих змінних не можна, проте всередині блоку доступні всі змінні із зовнішніх блоків.

### 9. Наведіть приклади, у яких випадках краще використовувати наступні оператори та конструкції:
- **`if`**: коли дію треба виконати лише за певної умови, а якщо умова хибна — нічого додаткового робити не треба (наприклад, перевірка аргументу: `if (k < 1) throw new IllegalArgumentException(...)`).
- **`if-else`**: коли є рівно дві взаємовиключні дії (наприклад, перевірка парності: `if (n % 2 == 0) { ... } else { ... }`).
- **ланцюги `if-else if -else if...`**: коли перевіряється діапазон значень або кілька різних умов (наприклад, шкала оцінювання: `>= 90` — A, `>= 75` — B, `>= 60` — C, інакше — F).
- **`switch`**: коли значення однієї змінної порівнюється з набором фіксованих константних значень (наприклад, обробка номера дня тижня 1..7 або вибір дії в текстовому меню).
- **тернарна умовна операція `?:`**: коли потрібно компактно обрати одне з двох значень і присвоїти його змінній (наприклад, `double sign = (i % 2 != 0) ? 1.0 : -1.0;`).

### 10. Наведіть приклади, у яких випадках краще використовувати наступні оператори та конструкції:
- **`while`**: коли кількість повторень наперед невідома, умова перевіряється перед виконанням, і цикл може не виконатися жодного разу (наприклад, обчислення суми ряду до досягнення точності $\varepsilon$).
- **`do-while`**: коли тіло циклу гарантовано має виконатися щонайменше один раз (наприклад, введення даних користувачем із повторенням у разі некоректного вводу).
- **`for`**: коли відома точна кількість ітерацій або є лічильник з визначеним діапазоном (наприклад, цикл від $i = 1$ до $k$, перебір елементів масиву).

### 11. Чим оператор break відрізняється від оператора continue?
- **`break`** — повністю перериває роботу циклу або конструкції `switch` і передає керування наступному оператору за межами циклу.
- **`continue`** — завершує лише **поточну ітерацію** циклу та одразу переходить до наступної (до перевірки умови або інкременту лічильника). Сам цикл при цьому продовжує працювати.

### 12. Навіщо у мові Java є мітки, якщо немає goto?
Мітки в Java використовуються разом з операторами `break` та `continue` для керування **вкладеними циклами**.  
За замовчуванням `break` перериває лише найближчий внутрішній цикл. Якщо потрібно вийти одразу з двох чи більше вкладених циклів, перед зовнішнім циклом ставиться мітка, наприклад:
```java
outerLoop:
for (int i = 0; i < 10; i++) {
    for (int j = 0; j < 10; j++) {
        if (i * j > 50) {
            break outerLoop; // вихід одразу з обох циклів
        }
    }
}
```

### 13. До якого результату призведе виконання наступного фрагменту коду? Перевірте. Поясніть.
```java
boolean a = false;
boolean b = false; 
if (a=false) {
    System.out.println("a is false");
} 
if (b=true) {
    System.out.println("b is true");
}
if (a=b) {
    System.out.println("a = b");
}
```
**Результат:**
```text
b is true
a = b
```
**Пояснення:**  
В усіх умовах використано оператор присвоєння `=` замість порівняння `==`. В Java оператор присвоєння повертає присвоєне значення:
1. `(a=false)` повертає `false`, умова хибна — рядок `"a is false"` не виводиться.
2. `(b=true)` присвоює змінній `b` значення `true` і повертає `true`, умова істинна — виводиться `"b is true"`.
3. `(a=b)` присвоює `a` поточне значення `b` (яке дорівнює `true`) і повертає `true`, умова істинна — виводиться `"a = b"`.

### 14. До якого результату призведе виконання наступного фрагменту коду? Перевірте. Поясніть.
```java
int a = 1;
a++;
++a; 
switch(a) {
    case 1: System.out.println("1");
    case 2: System.out.println("2");
    case 3: System.out.println("3");
    case 4: System.out.println("4"); 
}
```
**Результат:**
```text
3
4
```
**Пояснення:**  
1. Початково `a = 1`. Після `a++` значення стає 2, після `++a` — 3.
2. Оператор `switch(a)` знаходить відповідність у `case 3:` і виводить `3`.
3. Оскільки після `case 3:` відсутній оператор `break`, виникає ефект «провалювання» (fall-through). Програма продовжує виконання в наступній гілці `case 4:` і виводить `4`.

### 15. До якого результату призведе виконання наступного фрагменту коду (true/false)? Перевірте. Поясніть.
```java
double sum = 0; 
// Let's find: 1 + 1/2 + 1/3 + 1/4 + 1/5 + ...
for(int i=1; i<10; i++) {
    sum = sum + 1/i;
}
System.out.println(sum > 1);
```
**Результат:**
```text
false
```
**Пояснення:**  
Це класична пастка мови Java, пов'язана з цілочисельним діленням:
1. Число `1` та змінна `i` мають тип `int`.
2. Операція `1 / i` виконується як цілочисельне ділення (дрібна частина відкидається):
   - при $i = 1$: `1 / 1 = 1`;
   - при $i = 2$: `1 / 2 = 0` (а не 0.5);
   - при всіх наступних $i \ge 2$: результат ділення дорівнює `0`.
3. До змінної `sum` додається лише `1`, тому після закінчення циклу `sum = 1.0`.
4. Умова `sum > 1` (тобто `1.0 > 1`) є хибною, тому виведеться `false`.

  * **Цикл:** Використано цикл `for`.
  * **Клас:** `src/lab04/Task61.java`
  * **Приклади дозволених значень:**
    * $A = [2, -3, 5, -4, 0]$, $B = [3, -2, -1, 6, 5] \implies C = [5, 6, 0, 0, 0]$
    * $A = [10, -5, 0]$, $B = [4, -8, 0] \implies C = [14, 40, 0]$
  * **Перевірка помилкових значень:**
    * Різна довжина ($A$ має 3 елементи, $B$ має 2) $\implies$ викидає `IllegalArgumentException` ("Масиви A та B повинні бути однакової довжини!")
    * Порожні масиви $\implies$ викидає `IllegalArgumentException` ("Масиви не можуть бути порожніми!")
    * Передача `null` $\implies$ викидає `NullPointerException` ("Масиви не можуть бути null!")

## Відповіді на контрольні питання (до Лабораторної роботи №4)

### 1. Чим змінна відрізняється від масиву?
Звичайна (примітивна) змінна зберігає лише одне окреме значення певного типу.  
Масив — це структура даних (об'єкт у купі), яка містить фіксовану кількість однотипних елементів під одним спільним іменем, доступ до кожного з яких здійснюється за його цілочисельним номером (індексом).

### 2. Що таке стек? Що таке купа? Яка між ними різниця?
- **Стек (Stack):** відносно невелика, швидка область оперативної пам'яті, що працює за принципом LIFO (Last In, First Out). У ньому зберігаються виклики методів, локальні змінні та посилання на об'єкти. Пам'ять виділяється та звільняється автоматично при вході й виході з методу.
- **Купа (Heap):** велика динамічна область пам'яті, де створюються і зберігаються всі об'єкти (включно з масивами).
- **Різниця:** стек значно швидший, але обмежений за розміром; купа призначена для довготривалого зберігання динамічних об'єктів, а непотрібна пам'ять у ній очищується збирачем сміття (Garbage Collector).

### 3. Чи може змінна бути розташована у стеку? Безпосередньо у купі? В об’єкті у купі? Чи може масив бути розташований у стеку? Безпосередньо у купі? В об’єкті у купі?
- **Змінна:**
  - *У стеку:* **Так** (локальні змінні методів).
  - *Безпосередньо у купі:* **Ні** (окремо самі по собі змінні в купі не існують).
  - *В об'єкті у купі:* **Так** (поля екземпляра класу зберігаються всередині об'єкта в купі).
- **Масив:**
  - *У стеку:* **Ні** (масив у Java є об'єктом, тому завжди розташований у купі; у стеку зберігається лише посилання на нього).
  - *Безпосередньо у купі:* **Так** (при виклику `new int[...]` масив виділяється саме в купі).
  - *В об'єкті у купі:* Сам масив все одно розміщується в купі як окремий об'єкт, а в полі іншого об'єкта зберігається лише посилання на цей масив.

### 4. Чим посилання на масив відрізняється від масиву? Чи може посилання на масив бути розташовано у стеку? Безпосередньо у купі? В об’єкті у купі?
Масив — це безпосередньо сукупність комірок пам'яті з даними в купі. Посилання — це змінна, яка містить адресу ділянки пам'яті в купі, де цей масив розташований.
- Посилання у стеку: **Так** (локальна посилальна змінна, наприклад `int[] arr`).
- Посилання безпосередньо у купі: **Ні** (хіба що як елемент масиву об'єктних посилань).
- Посилання в об'єкті у купі: **Так** (поле класу, що посилається на масив).

### 5. Якщо масив складається з 10 комірок, які індекси мають перша та остання комірки?
- Перша комірка: індекс `0`.
- Остання комірка: індекс `9` (довжина мінус один: $10 - 1 = 9$).

### 6. Що буде, якщо звернутися до неіснуючої комірки у масиві?
Виникне виключення часу виконання (помилка) `ArrayIndexOutOfBoundsException`.

### 7. При створенні нового масиву без явної ініціалізації усі його комірки будуть проініціалізовані:
- **спеціальними значеннями за замовчуванням** (для цілих чисел — `0`, для дійсних — `0.0`, для логічних — `false`, для посилань на об'єкти — `null`).

### 8. Як дізнатися номер першої та останньої комірки масиву, якщо відомо лише посилання на нього?
- Номер першої комірки: завжди `0` (за умови, що масив не порожній, `length > 0`).
- Номер останньої комірки: вираз `arr.length - 1`.

### 9. Як змінити розмір масиву?
Розмір масиву в Java змінити неможливо, оскільки він фіксується під час виділення пам'яті. Щоб «змінити розмір», створюють новий масив необхідної довжини і копіюють у нього елементи старого масиву (вручну або методами `Arrays.copyOf()` / `System.arraycopy()`).

### 10. Що відбувається з масивом при копіюванні посилання на нього?
Новий масив не створюється. Обидва посилання починають вказувати на один і той самий об'єкт масиву в купі. Зміна будь-якого елемента через одне посилання миттєво відображається і через інше.

### 11. Що відбувається з масивом при втрачанні посилання на нього?
Масив стає недосяжним (unreachable). Пам'ять, яку він займав, позначається як вільна та автоматично очищується збирачем сміття (Garbage Collector).

### 12. Чим відрізняються конструкції «for» та «for-each» при роботі з масивами? Які переваги та недоліки кожного з варіантів?
- **`for` (традиційний):**
  - *Переваги:* доступ до індексу `i`; можливість модифікувати значення елементів масиву; можливість обходити масив у зворотному напрямку або з довільним кроком; робота з декількома масивами одночасно.
  - *Недоліки:* більш громіздкий синтаксис; ризик виходу за межі масиву (`ArrayIndexOutOfBoundsException`).
- **`for-each` (розширений):**
  - *Переваги:* простий і компактний синтаксис; виключає помилки виходу за межі масиву.
  - *Недоліки:* відсутній доступ до індексу; елементи доступні лише для читання; обхід можливий лише послідовно від початку до кінця.

### 13. Чи можна у масив «double[]» записати значення «int»? Чи можна у масив «int[]» записати значення «double»?
- У масив `double[]` записати `int` **можна**, оскільки Java автоматично виконує неявне розширювальне перетворення типів (наприклад, число `5` автоматично запишеться як `5.0`).
- У масив `int[]` записати `double` **не можна** без явного приведення типу `(int)`, оскільки це призводить до втрати точності (відкидання дробової частини), і компілятор повідомить про помилку `incompatible types: possible lossy conversion from double to int`.
